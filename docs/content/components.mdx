# Components

<Callout type="info">
In a scaffolded project, everything in `components/ui`, `auth`, `dashboard`, `email`, `theme` and `providers` is a one-line re-export of the package. To restyle or change one, replace that file with your own code; it then stops receiving updates. Often it's easier to write a new component that wraps the shipped one. `components/site/` is your own code, except `cookie-banner.tsx`, which is a re-export too. See [Your project and the package](/architecture#your-project-and-the-package).
</Callout>

## UI primitives (`components/ui/`)

[shadcn/ui](https://ui.shadcn.com) (new-york style) on Radix UI and Tailwind 4:

`alert-dialog`, `avatar`, `badge`, `button`, `card`, `checkbox`, `data-table`, `dialog`, `dropdown-menu`, `file-upload`, `input`, `label`, `password-input`, `select`, `separator`, `sheet`, `sidebar`, `skeleton`, `switch`, `table`, `textarea`, `tooltip`

```tsx
import { Button } from "@/components/ui/button"
import { Card, CardHeader, CardTitle, CardContent } from "@/components/ui/card"
```

Add more with `bunx shadcn@latest add <name>`. The config is in `components.json`. Adding a component that already exists, such as `button`, overwrites the re-export with shadcn's source, and that file becomes yours.

- `password-input` is an `Input` with a show/hide toggle.
- `file-upload` (Beta) collects photos or files from the camera, the gallery and drag and drop. Every method is **off by default**; turn each one on with a prop. It renders nothing if none are on. It only collects files; the app decides where to send them.

  ```tsx
  import { FileUpload } from "@/components/ui/file-upload"

  <FileUpload camera gallery dragDrop maxFiles={5} maxSizeMB={10} onFilesChange={setFiles} />
  ```

  | Prop | Default | Notes |
  |---|---|---|
  | `camera` | `false` | "Take photo" button (`capture="environment"`). Opens the rear camera on mobile and a file picker on desktop. |
  | `gallery` | `false` | "Choose from gallery" button. |
  | `dragDrop` | `false` | Drop zone. |
| `clickable` | `false` | Pressing the drop zone opens the picker and the separate buttons are hidden. On a touch screen with `camera` and `gallery` both on, a tap asks "Take photo" or "Choose from gallery" (see `chooser`). A mouse click or Enter/Space opens the gallery directly, since the camera only opens a file picker on desktop. With only one source on, it opens that picker directly. The text reads "Tap to add files" on touch screens and "…or click to browse" elsewhere. Needs `dragDrop`. |
| `chooser` | `"sheet"` | How `clickable` asks on touch screens: `"sheet"` slides up from the bottom (within thumb reach, like the native iOS/Android choice), `"modal"` is a centered dialog. |
  | `accept` | `"image/*"` | Same format as `<input accept>`. Also checked on dropped files. |
  | `multiple` | `true` | `false` keeps one file and replaces it on each pick. |
  | `maxFiles`, `maxSizeMB` | none | Extra files and oversized files are rejected with an inline message. |
  | `disabled` | `false` | |
  | `icon` | upload icon | Drop zone icon, any React node. `null` hides it. |
  | `label` | "Drag and drop files here" | Drop zone text, any React node. |
  | `description` | — | Smaller sub text under the label, any React node. |
  | `dropzoneClassName` | — | Extra classes for the dashed drop zone box. |
  | `labelClassName` | — | Extra classes for the label text. |
  | `descriptionClassName` | — | Extra classes for the description text. |
  | `onFilesChange` | | Called with the full current list after every add or remove. |

- `data-table` is a paginated table that hides columns as the container narrows (`lib/utils/recalculate-columns.ts`). `components/dashboard/settings/sessions/sessions-card.tsx` is a working example.

  Each column can set `priority` (a number, default = its index) to control what survives on narrow screens:
  - Columns hide in descending `priority` order (ties: rightmost first). The best-priority column is never hidden, so a negative `priority` makes a column the anchor.
  - Once the table is collapsed, the remaining columns are also shown in `priority` order, so a negative value puts a column first. Wide screens keep the declared order and show every column.
  - `minWidth` is what the collapse math uses. Set it to the column's real width (for example long emails), or the column fits on paper and the table scrolls sideways.
  - Hidden columns move into the expandable row (the arrow on the left).
  - Example: the admin audit-log table sets `priority: -1` and `minWidth: 260` on User and `priority: 0` on Time, so phones show only User (name and email).

## Dashboard (`components/dashboard/`)

These are presentational components. Fetch data with the query helpers in a server component and pass it in as props.

| Component | Purpose |
|---|---|
| `dashboardHeader`, `appSidebar` | Navigation. `dashboardHeader` takes optional `brandName`, `brandHref` and `navLinks`. |
| `topNav`, `navStyleToggle` | Second dashboard navigation style. A header with the links, avatar and log-out. Below `md` the links move to a fixed bottom tab bar, which turns into the admin sub-menu (Admin home, Users, Audit logs, System settings, plus an **Exit** tab to `/dashboard`) while the user is inside `/dashboard/admin`. `navStyleToggle` is the header button that switches between sidebar and top bar. The choice is a per-browser `nav-style` cookie (`sidebar` default, or `topbar`) that `app/dashboard/layout.tsx` reads. It is not stored in the DB. |
| `profileCard`, `accountDetailsCard`, `verifyEmailButton` | Profile |
| `sessionsCard` / `sessionsSection` | Active sessions with revoke |
| `activityLogsCard` / `activityLogsSection` | Personal activity |
| `twoFactorCard`, `passkeysCard`, `deleteAccountCard` | Settings → Security and Danger zone |
| `installAppCard` | Settings → This device. Install steps for the visitor's own OS and browser, an **Install app** button where the browser supports it, and a confirmation once it runs installed. See [Installable app](/deployment#installable-app-pwa-beta). |
| `feedbackDialog` (Beta) | **Feedback** button in the dashboard header. It opens a bug report / general feedback form that posts to `/api/feedback`. The layout renders it only when a destination is configured. See [Feedback](/configuration#feedback-beta). |
| `impersonationBanner`, `heartbeat` | App-wide helpers |
| `sectionErrorFallback`, `*Skeleton` | Error boundary fallback and loading states |
| `admin/*` | Admin stats, users table, user detail cards, device cards, settings form |

`*Section` components are async server components that fetch data and render the matching `*Card`. The page wraps each one in `<ErrorBoundary fallback={<SectionErrorFallback />}>` and `<Suspense fallback={<…Skeleton />}>`, so one slow or failing widget doesn't block the rest. `app/dashboard/page.tsx` shows the pattern to copy.

## Email (`components/email/`)

[React Email](https://react.email) templates, sent through Resend:

| Template | Sent when |
|---|---|
| `auth/reset-password` | Password reset requested |
| `auth/verify-email` | User asks to verify their email |
| `security/new-device-alert` | First sign-in from a device (to the user and admins) |
| `security/passkey-changed` | Passkey added or removed |
| `auth/welcome`, `layout/base-layout`, `marketing/general-announcement` | Demo templates for `/api/send` |

**Before sending real email:**

1. Verify a sending domain in Resend.
2. Set `RESEND_API_KEY`.
3. Set `EMAIL_FROM` to an address on that domain, e.g. `My App <noreply@myapp.com>`.

The auth emails (reset, verification, new device, passkey change) are sent by the package's auth, using its own copies of these templates. To change their wording or design, use your own `server/auth.ts` (see [Customizing package code](/architecture#customizing-package-code)).

Sending your own email:

```ts
import { getResend, EMAIL_FROM } from "@/lib/email/resend"
import { EmailTemplateWelcome } from "@/components/email/auth/welcome"

await (await getResend()).emails.send({
  from: EMAIL_FROM,
  to: [user.email],
  subject: "Welcome!",
  react: EmailTemplateWelcome({ firstName: user.name }),
})
```

`resend` and `@react-email/components` are imported lazily, so a project that never sends email doesn't need them installed.

## Theme

`ThemeProvider` (`components/providers/theme-provider.tsx`, next-themes, `attribute="class"`) is mounted in the root layout. `ThemeToggle` (`components/theme/theme-toggle.tsx`) switches between light, dark and system. Theme tokens are in `styles/theme.css`.

## Changelog and update modal

`data/changelog.json` drives `/changelog` and the "what's new" modal (`components/updates/`). Add an entry there for each release.
