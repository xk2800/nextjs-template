# Components

<Callout type="info">
In a scaffolded project, everything in `components/ui`, `auth`, `dashboard`, `email`, `theme` and `providers` is a one-line re-export of the package. To restyle or change one, replace that file with your own code; it then stops receiving updates. Often it's easier to write a new component that wraps the shipped one. `components/site/` is your own code, except `cookie-banner.tsx`, which is a re-export too. See [Your project and the package](/architecture#your-project-and-the-package).
</Callout>

## UI primitives (`components/ui/`)

[shadcn/ui](https://ui.shadcn.com) (new-york style) on Radix UI and Tailwind 4:

`alert-dialog`, `avatar`, `badge`, `button`, `card`, `checkbox`, `data-table`, `dialog`, `dropdown-menu`, `input`, `label`, `password-input`, `separator`, `sheet`, `sidebar`, `skeleton`, `switch`, `table`, `textarea`, `tooltip`

```tsx
import { Button } from "@/components/ui/button"
import { Card, CardHeader, CardTitle, CardContent } from "@/components/ui/card"
```

Add more with `bunx shadcn@latest add <name>`. The config is in `components.json`. Adding a component that already exists, such as `button`, overwrites the re-export with shadcn's source, and that file becomes yours.

- `password-input` is an `Input` with a show/hide toggle.
- `data-table` is a paginated table that hides columns as the container narrows (`lib/recalculate-columns.ts`). `/dashboard/data-table` is a working example.

|---|---|

| `loginErrorRecovery` | Retries a stale OAuth `please_restart_the_process` error |
| `logoutButtons` | Sign out |

## Dashboard (`components/dashboard/`)

These are presentational components. Fetch data with the query helpers in a server component and pass it in as props.

| Component | Purpose |
|---|---|
| `dashboardHeader`, `appSidebar` | Navigation. `dashboardHeader` takes optional `brandName`, `brandHref` and `navLinks`. |
| `profileCard`, `accountDetailsCard`, `verifyEmailButton` | Profile |
| `sessionsCard` / `sessionsSection` | Active sessions with revoke |
| `activityLogsCard` / `activityLogsSection` | Personal activity |
| `twoFactorCard`, `passkeysCard`, `deleteAccountCard` | Settings → Security and Danger zone |
| `impersonationBanner`, `heartbeat` | App-wide helpers |
| `sectionErrorFallback`, `*Skeleton` | Error boundary fallback and loading states |
| `admin/*` | Admin stats, users table, user detail cards, device cards, settings form |

`*Section` components are async server components that fetch data and render the matching `*Card`. The page wraps each one in `<ErrorBoundary fallback={<SectionErrorFallback />}>` and `<Suspense fallback={<…Skeleton />}>`, so one slow or failing widget doesn't block the rest. `app/dashboard/page.tsx` shows the pattern to copy.

## Email (`components/email/`)

[React Email](https://react.email) templates, sent through Resend:

| Template | Sent when |
|---|---|
| `email-template-reset-password` | Password reset requested |
| `email-template-verify-email` | User asks to verify their email |
| `email-template-new-device` | First sign-in from a device (to the user and admins) |
| `email-template-passkey-change` | Passkey added or removed |
| `email-template-welcome`, `email-template`, `email-template-2` | Demo templates for `/api/send` |

**Before sending real email:**

1. Verify a sending domain in Resend.
2. Set `RESEND_API_KEY`.
3. Set `EMAIL_FROM` to an address on that domain, e.g. `My App <noreply@myapp.com>`.

The auth emails (reset, verification, new device, passkey change) are sent by the package's auth, using its own copies of these templates. To change their wording or design, use your own `server/auth.ts` (see [Customizing package code](/architecture#customizing-package-code)).

Sending your own email:

```ts
import { getResend, EMAIL_FROM } from "@/lib/resend"
import { EmailTemplateWelcome } from "@/components/email/email-template-welcome"

await (await getResend()).emails.send({
  from: EMAIL_FROM,
  to: [user.email],
  subject: "Welcome!",
  react: EmailTemplateWelcome({ firstName: user.name }),
})
```

`resend` and `@react-email/components` are imported lazily, so a project that never sends email doesn't need them installed.

## Theme

`ThemeProvider` (`components/providers/theme-provider.tsx`, next-themes, `attribute="class"`) is mounted in the root layout. `ThemeToggle` (`components/theme/theme-toggle.tsx`) switches between light, dark and system. Theme tokens are in `styles/theme.css`.

## Changelog and update modal

`data/changelog.json` drives `/changelog` and the "what's new" modal (`components/Updates/`). Add an entry there for each release.
