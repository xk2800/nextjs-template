# Next.js Template

A production-ready Next.js starter with authentication, an admin dashboard, security features (2FA, passkeys, device alerts) and a shadcn/ui component library. Create a project with **`@xk2800/create-nextjs`**. Your app's code stays yours, and the auth, database and UI logic come from the [`@xk2800/nextjs-template`](/npm-package) package, so you get fixes with a version bump.

## Tech Stack

| Technology | Version | Purpose |
|---|---|---|
| [Next.js](https://nextjs.org) | 16 | React framework (App Router, `proxy.ts`) |
| [React](https://react.dev) | 19 | UI library |
| [TypeScript](https://typescriptlang.org) | 6 | Type safety |
| [Drizzle ORM](https://orm.drizzle.team) | 0.45 | Database ORM + migrations |
| [PostgreSQL](https://postgresql.org) | — | Database (`pg` driver or Neon HTTP driver) |
| [Better-Auth](https://better-auth.com) | 1.7 | Authentication (+ admin, 2FA, passkey, One Tap plugins) |
| [Tailwind CSS](https://tailwindcss.com) | 4 | Styling |
| [shadcn/ui](https://ui.shadcn.com) | — | Component library (new-york style) |
| [Bun](https://bun.sh) | 1.x | Package manager & script runner |
| [Resend](https://resend.com) + React Email | 6 | Transactional email |

## Quick Start

You need **[Bun](https://bun.sh)**, **Git**, and a **PostgreSQL** database (local, Docker or Neon).

<Steps>

### Create the project

Run this from the folder you want the project created in:

<Tabs items={['npx', 'bunx']}>
  <Tabs.Tab>
```bash
npx @xk2800/create-nextjs
```
  </Tabs.Tab>
  <Tabs.Tab>
```bash
bunx @xk2800/create-nextjs
```
  </Tabs.Tab>
</Tabs>

It asks for:

- **Project name.** Used as the folder name and the `package.json` name. Enter `.` to use the current (empty) folder.
- **Database driver.** `pg` for local or self-hosted Postgres, `neon` for Neon.
- **Optional modules.** Doppler, Resend email and Docker (a `Dockerfile`).

It then copies the template and creates `.env.development`. That file comes with a generated `BETTER_AUTH_SECRET` and `BETTER_AUTH_URL=http://localhost:3000`. The CLI also runs `bun install`, generates one initial migration and makes the first git commit.

<Callout type="info">
The CLI needs a real terminal for its prompts. It won't run in CI or in some IDE task panels (`ERR_TTY_INIT_FAILED`).
</Callout>

### Point it at your database

```bash
cd my-app
```

In `.env.development`, set `DATABASE_URL`:

```bash
DATABASE_URL=postgres://user:pass@localhost:5432/myapp
```

Google sign-in and email are optional for now. See [Configuration](/configuration) for every variable.

### Check your setup

```bash
bun run doctor
```

This checks your env, the auth secret and the database connection. Fix anything marked `✗`. A warning that 1 migration is pending is expected here; the next step applies it.

### Create the tables

```bash
bun run migrate:dev
```

### Start the app

```bash
bun dev
```

Open `http://localhost:3000` and sign up with email and password.

### Make yourself an admin

New accounts are always `user`. Promote your own account once in SQL, or edit the row in `bun run studio:dev`:

```sql
UPDATE "user" SET roles = 'admin' WHERE email = 'you@example.com';
```

Sign out and back in, then open `/dashboard/admin`.

</Steps>

<Callout type="info">
In SQL the role column is called `roles`. In TypeScript and on the session object it's `role`. After the first admin exists, change roles from the admin dashboard.
</Callout>

## Getting updates

The template's auth, database, query and UI code comes from the `@xk2800/nextjs-template` package, so updating it is a dependency bump:

```bash
bun update @xk2800/nextjs-template
bun run generate      # only if the release changed the schema
bun run migrate:dev
```

See [Your project and the package](/architecture#your-project-and-the-package) for which files that covers and how to customize them.

## Scripts

| Script | What it does |
|---|---|
| `bun dev` | Dev server with Turbopack |
| `bun run build` / `bun start` | Production build and server |
| `bun run doctor` | Checks env, auth secret, DB connection and pending migrations (reads `.env.development`) |
| `bun run generate` | Generates a migration from `server/db/schema.ts` |
| `bun run migrate:dev` / `:prod` / `:test` | Applies migrations using `.env.development` / `.env.production` / `.env.test` |
| `bun run studio:dev` / `:prod` | Drizzle Studio |
| `bun run test` | Unit tests for pure logic |
| `bun run typecheck` | `tsc --noEmit` |
| `bun run *:doppler` | The same commands with secrets from Doppler (if you picked that module). See [Configuration](/configuration#doppler). |

## What's included

- **Auth:** email/password, Google OAuth, Google One Tap, passkeys, TOTP 2FA, password reset and email verification. Sessions are stored in the database. See [Authentication](/authentication).
- **Security:** new-device email alerts, a sign-in/sign-up abuse throttle, active-session revocation, self-serve account deletion and a cookie-consent banner. See [Security Features](/security).
- **Admin:** user management (role, ban, delete, bulk actions, CSV export), impersonation, a system-wide activity log, device-security cards, live auth toggles and maintenance mode. See [Admin & Maintenance](/admin).
- **Activity log:** sign-ins, failed sign-ins, admin actions, passkey changes and impersonation are all recorded.
- **UI:** shadcn/ui primitives, dashboard cards, dark mode and a changelog page driven by `data/changelog.json`.
