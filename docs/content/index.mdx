# Next.js Template

A production-ready Next.js starter with authentication, an admin dashboard, security features (2FA, passkeys, device alerts) and a shadcn/ui component library. Clone it to start an app, or install the reusable parts from npm as [`@xk2800/nextjs-template`](/npm-package).

## Tech Stack

| Technology | Version | Purpose |
|---|---|---|
| [Next.js](https://nextjs.org) | 16 | React framework (App Router, `proxy.ts`) |
| [React](https://react.dev) | 19 | UI library |
| [TypeScript](https://typescriptlang.org) | 6 | Type safety |
| [Drizzle ORM](https://orm.drizzle.team) | 0.45 | Database ORM + migrations |
| [PostgreSQL](https://postgresql.org) | — | Database (`pg` driver or Neon HTTP driver) |
| [Better-Auth](https://better-auth.com) | 1.7 | Authentication (+ admin, 2FA, passkey, One Tap plugins) |
| [Tailwind CSS](https://tailwindcss.com) | 4 | Styling |
| [shadcn/ui](https://ui.shadcn.com) | — | Component library (new-york style) |
| [Bun](https://bun.sh) | 1.x | Package manager & script runner |
| [Resend](https://resend.com) + React Email | 6 | Transactional email |

## Quick Start

You need **Bun** and a **PostgreSQL** database (local, Docker or Neon).

<Steps>

### Clone and install

```bash
git clone https://github.com/xk2800/nextjs-template.git
cd nextjs-template
bun install
```

### Create your env file

```bash
cp .env.development.example .env.development
```

At minimum, set:

```bash
DATABASE_URL=postgres://user:pass@localhost:5432/myapp
BETTER_AUTH_URL=http://localhost:3000
NEXT_PUBLIC_APP_URL=http://localhost:3000
BETTER_AUTH_SECRET=   # output of: openssl rand -base64 32
```

Google sign-in and email are optional at this point. See [Configuration](/configuration) for every variable.

### Create the tables

```bash
bun run migrate:dev
```

### Check your setup

```bash
bun run doctor
```

This checks the env schema, the database connection and whether any migrations are still pending. Fix anything marked `✗` before moving on.

### Start the app

```bash
bun dev
```

Open `http://localhost:3000` and sign up with email and password.

### Make yourself an admin

New accounts are always `user`. Promote your own account once in SQL (or edit the row in `bun run studio:dev`):

```sql
UPDATE "user" SET roles = 'admin' WHERE email = 'you@example.com';
```

Sign out and back in, then open `/dashboard/admin`.

</Steps>

<Callout type="info">
The role column is called `roles` in the database, while the TypeScript field and session object call it `role`. After the first admin exists, change roles from the admin dashboard instead.
</Callout>

## Scripts

| Script | What it does |
|---|---|
| `bun dev` | Dev server with Turbopack |
| `bun run build` | Builds the npm package (`tsup`), then `next build` |
| `bun start` | Production server |
| `bun run test` | Unit tests for pure logic (throttle limits, maintenance paths, etc.) |
| `bun run typecheck` | `tsc --noEmit` against the package build config |
| `bun run doctor` | Env, DB connection and pending-migration check (reads `.env.development`) |
| `bun run generate` | Generate a migration from `server/db/schema.ts` |
| `bun run migrate:dev` / `:prod` / `:test` | Apply migrations using `.env.development` / `.env.production` / `.env.test` |
| `bun run studio:dev` / `:prod` | Drizzle Studio |
| `bun run *:doppler` | Same as above but secrets come from Doppler. See [Configuration](/configuration#doppler) |
| `bun run docs:dev` | This docs site on port 3001 |

## What's included

- **Auth:** email/password, Google OAuth, Google One Tap, passkeys and TOTP 2FA, with password reset and email verification. Sessions are stored in the database. See [Authentication](/authentication).
- **Security:** new-device email alerts, a sign-in/sign-up abuse throttle, active-session revocation, self-serve account deletion and a cookie-consent banner. See [Security Features](/security).
- **Admin:** user management (role, ban, delete, bulk actions, CSV export), impersonation, a system-wide activity log, device-security cards, live auth toggles and maintenance mode. See [Admin & Maintenance](/admin).
- **Activity log:** sign-ins, failed sign-ins, admin actions, passkey changes and impersonation are all recorded.
- **UI:** shadcn/ui primitives, dashboard cards, dark mode and a changelog page driven by `data/changelog.json`.
