# Database

## Overview

The app uses [Drizzle ORM](https://orm.drizzle.team) with PostgreSQL. `server/db/index.ts` picks the driver from `DB_DRIVER`:

| `DB_DRIVER` | Driver | Use for |
|---|---|---|
| `pg` (default) | `node-postgres` pool | Local, Docker or any long-running server. Set `DATABASE_SSL=true` for managed Postgres. |
| `neon` | `@neondatabase/serverless` HTTP | Neon from serverless hosts |

`db` is `server-only`. Import it only from server components, route handlers and server actions.

```ts
import { db } from "@/server/db"
import { users } from "@/server/db/schema"
import { eq } from "drizzle-orm"

const [user] = await db.select().from(users).where(eq(users.email, email)).limit(1)
```

<Callout type="info">
Query logging is on (`logger: true`), so every SQL statement prints to the server console. Turn it off in `server/db/index.ts` if the noise bothers you.
</Callout>

## Tables

Everything is defined in `server/db/schema.ts`. IDs are CUID2 strings. Every user-owned table has `ON DELETE CASCADE` to `user.id`, so deleting a user removes all their rows.

| Table (export) | Purpose |
|---|---|
| `user` (`users`) | Profile, role, ban state, `lastLoginAt`, `lastActiveAt`, `twoFactorEnabled` |
| `session` (`sessions`) | Database-backed sessions. `impersonatedBy` is set while an admin impersonates the user. |
| `account` (`accounts`) | One row per sign-in method. Credential passwords live here (`providerId = 'credential'`), **not** on `user`. |
| `verification` (`verifications`) | Tokens for email verification, password reset and OAuth state |
| `twoFactor` (`twoFactors`) | TOTP secret and encrypted backup codes (Better-Auth plugin) |
| `passkey` (`passkeys`) | WebAuthn credentials (Better-Auth plugin) |
| `activity_log` (`activityLogs`) | Audit trail. `action` is the `activity_actions` enum. Login rows also store OS, browser, device and geo. |
| `device_fingerprint` (`deviceFingerprints`) | One row per (user, FingerprintJS visitorId) pair. A missing row means a new device, which triggers an alert. |
| `auth_throttle` (`authThrottle`) | Fixed-window counters for the sign-in/sign-up throttle, keyed by fingerprint or `ip:<addr>` |
| `system_settings` (`systemSettings`) | Single row (`id = 'default'`) holding admin-editable settings |

### Column-name gotchas

- The role column is **`roles`** in SQL (`RoleEnum('roles')`) but `role` in TypeScript and on the session user. Raw SQL has to use `roles`.
- `user.password` exists but is unused. Better-Auth stores hashed passwords in `account.password`.
- Table names are singular and some are camelCase (`"user"`, `"twoFactor"`), so quote them in raw SQL.

### Enums

```sql
roles:            'user' | 'admin'
activity_actions: 'login' | 'logout' | 'login_failed' | 'password_changed'
                | 'email_changed' | 'profile_updated' | 'session_revoked'
                | 'user_deleted' | 'user_banned' | 'user_unbanned' | 'role_changed'
                | 'impersonation_started' | 'impersonation_stopped'
                | 'settings_changed' | 'passkey_added' | 'passkey_removed'
```

## Changing the schema

1. Edit `server/db/schema.ts`.
2. Generate a migration:
   ```bash
   bun run generate
   ```
   This writes SQL to `server/drizzle/`. **Commit the migration files.**
3. Apply it:
   ```bash
   bun run migrate:dev    # .env.development
   bun run migrate:prod   # .env.production
   bun run migrate:test   # .env.test
   ```
4. Run `bun run doctor` to confirm nothing is pending. The check only works with `DB_DRIVER=pg`.

<Callout type="warning">
If you change a table that Better-Auth owns (`user`, `session`, `account`, `verification`, `twoFactor`, `passkey`), keep column names and types the way the plugin expects. Add custom user fields to `user.additionalFields` in `server/auth.ts` and to `better-auth.d.ts` as well.
</Callout>

`drizzle.config.ts` reads `process.env.DATABASE_URL` directly instead of importing `config/env`, because drizzle-kit runs outside Next.js and the `server-only` guard would throw there.


## Testing the connection

```bash
bun run doctor                                                    # quick check (dev env)
bun --env-file=.env.production scripts/doctor.ts                  # quick check (any env)
bun --env-file=.env.development server/test-connection/index.ts   # insert/read/update/delete round-trip
```
