# Authentication

Auth is [Better-Auth](https://better-auth.com) 1.7 with the Drizzle adapter. All config lives in `createAuth()` in `server/auth.ts`, and `auth` is the default instance. The HTTP handler is `app/api/auth/[...all]/route.ts`, which serves everything under `/api/auth/*`.

## Sign-in methods

| Method | On by default | Switch | Notes |
|---|---|---|---|
| Email + password | Yes | `AUTH_ENABLE_EMAIL_PASSWORD` | Better-Auth's default hashing (scrypt). Includes password reset. |
| Google OAuth | Yes | `AUTH_ENABLE_GOOGLE` | Needs `AUTH_GOOGLE_ID` / `AUTH_GOOGLE_SECRET` |
| Google One Tap | No | `AUTH_ENABLE_ONE_TAP` **and** `NEXT_PUBLIC_AUTH_ENABLE_ONE_TAP` | Also needs Google enabled and cookie consent. |
| Passkey (WebAuthn) | Yes | — | Users register a passkey in Settings first. |
| TOTP 2FA | Per user | — | A second step after email/password sign-in. See [Security](/security#two-factor-authentication). |

A disabled env flag removes the provider from the Better-Auth config, so its endpoints reject requests even if someone calls them directly. The login and signup pages hide it as well. Admins can also turn Google, email/password and One Tap off live from System Settings. See [Env vs. System Settings](/configuration#env-vs-system-settings).

If every provider ends up disabled, `createAuth()` throws "No auth provider is enabled". It throws on the first use of `auth`, not on import.

### Setting up Google OAuth

1. In Google Cloud Console, create an **OAuth client ID** of type *Web application*.
2. Add this **Authorized redirect URI**: `{BETTER_AUTH_URL}/api/auth/callback/google`, for example `http://localhost:3000/api/auth/callback/google`.
3. For One Tap, also add your origin under **Authorized JavaScript origins**.
4. Put the ID and secret in `AUTH_GOOGLE_ID` / `AUTH_GOOGLE_SECRET`. For One Tap, also copy the ID to `NEXT_PUBLIC_GOOGLE_CLIENT_ID`.

### Password reset and email verification

These are wired to Resend, so they need `RESEND_API_KEY` and a valid `EMAIL_FROM` in `lib/resend.ts`.

- **Reset:** `/forgot-password` calls `authClient.requestPasswordReset()`, which emails a link to `/reset-password`.
- **Verification** is opt-in: `requireEmailVerification` is `false`. Users send themselves a verification link from the dashboard, and clicking it sets `user.emailVerified`.

To make verification mandatory, set `emailAndPassword.requireEmailVerification: true` in `server/auth.ts`.

### Adding another provider

Pass extra `socialProviders` to `createAuth()`. They're merged with Google, not swapped in for it:

```ts
export const auth = createAuth({
  socialProviders: {
    github: { clientId: process.env.GITHUB_CLIENT_ID!, clientSecret: process.env.GITHUB_CLIENT_SECRET! },
  },
})
```

Then add a button that calls `authClient.signIn.social({ provider: "github" })`. `components/auth/socialLogin.tsx` only covers Google. In this repo you can edit `server/auth.ts` directly. For the package version, see [Using as a Package](/npm-package#adding-a-social-provider).

## Sessions

| Setting | Value |
|---|---|
| Lifetime | 30 days |
| Refreshed in DB | every 24 h of activity |
| Cookie cache | 5 minutes |

Sessions live in the `session` table, so they can be listed and revoked. Because of the 5-minute cookie cache, a revoked session can stay valid for up to 5 minutes in places that read the cached cookie.

Each new session (sign-in) updates `user.lastLoginAt` and writes a `login` activity row with IP, device and geo data. A client heartbeat keeps `user.lastActiveAt` current.

## Server-side usage

```ts
import { getCurrentSession, requireAuth, requireRole, hasRole } from "@/lib/auth-helpers"

const session = await getCurrentSession()   // session or null
const session = await requireAuth()         // redirects to /login; signs out banned users
const session = await requireRole("admin")  // also redirects non-admins to /dashboard
hasRole(session.user.role, "admin")         // boolean, for conditional UI
```

`getCurrentSession` and `requireAuth` are wrapped in React `cache()`, so calling them from both a layout and a page costs one lookup.

Inside route handlers, call Better-Auth directly:

```ts
import { auth } from "@/server/auth"
import { headers } from "next/headers"

const session = await auth.api.getSession({ headers: await headers() })
```

### Redirect safety

Always pass user-supplied `callbackUrl` values through `normalizeCallbackUrl()` before redirecting. It drops anything that isn't same-origin and returns `/dashboard` in its place.

## Client-side usage

```tsx
"use client"
import { authClient, useSession } from "@/lib/auth-client"

const { data: session, isPending } = useSession()

await authClient.signIn.email({ email, password })
await authClient.signIn.social({ provider: "google", callbackURL: "/dashboard" })
await authClient.signIn.passkey()
await authClient.signOut()
```

The client has the admin, twoFactor and passkey plugins loaded, plus One Tap when it's enabled. So `authClient.admin.*`, `authClient.twoFactor.*` and `authClient.passkey.*` are available.

<Callout type="info">
If `signIn.email` returns `{ twoFactorRedirect: true }`, send the user to `/login/2fa`. `components/auth/emailPasswordLogin.tsx` already does this.
</Callout>

## Roles

- `user` (default) or `admin`. The field has `input: false`, so users can't set it during sign-up.
- Change roles from the admin dashboard. The API blocks changing your own role and demoting the last admin.
- **First admin:** see [Quick Start](/#make-yourself-an-admin).

## Hooks in `server/auth.ts`

Built-in behavior you might want to change. All of it is in `hooks.before`, `hooks.after` and `databaseHooks`:

- **Abuse throttle** on `/sign-in/email` and `/sign-up/email`. See [Security](/security#sign-in-throttle).
- **Live provider kill-switch**: reads System Settings on every sign-in attempt.
- **Account deletion guards**: blocks deletion while impersonating and blocks deleting the last admin.
- **Login logging**: sets `lastLoginAt` and writes the activity row, including referrer and geo.
- **Impersonation audit**: logs `impersonation_started` and `impersonation_stopped`.
- **Passkey change emails**: sent on add or remove.
- **OAuth double-callback recovery**: `onAPIError.errorURL = "/login"`, so a duplicate callback lands the user signed in instead of on an error page.

## Type extensions

`better-auth.d.ts` adds `role` and `twoFactorEnabled` to the `User` type. If you add a field to `user.additionalFields`, add it there too.
