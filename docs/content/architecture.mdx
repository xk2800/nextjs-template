# Architecture

## Your project and the package

A project created with `create-nextjs` contains two kinds of files:

| Kind | Examples | Who owns it |
|---|---|---|
| **Your code** | everything in `app/`, `proxy.ts`, `components/site/` (except `cookie-banner.tsx`), any new file you create, `lib/site.ts`, `data/changelog.json` | You. Edit freely. |
| **Re-exports of the package** | `server/auth.ts`, `server/db/*`, `config/env.ts`, `lib/auth-helpers.ts`, `lib/auth-client.ts`, `lib/*-queries.ts`, `lib/activity-logger.ts`, `lib/maintenance.ts`, `lib/cookie-consent.ts`, `lib/utils.ts`, `components/{ui,auth,dashboard,email,theme,providers}/*` and `components/site/cookie-banner.tsx` | `@xk2800/nextjs-template`. Each file is one line: `export * from '@xk2800/nextjs-template/…'`. |

Your imports don't change: `import { auth } from "@/server/auth"` keeps working, and the code behind it comes from `node_modules`. `bun update @xk2800/nextjs-template` updates all of the re-exported files at once.

### Customizing package code

- **To customize a re-exported file,** replace its one line with your own code. Copy the original from the [template repo](https://github.com/xk2800/nextjs-template) at the tag matching your installed version (`v<version>`), then edit it. From then on that file is yours and **stops receiving updates**, so only do this when you need to.
- **Prefer configuration first.** Env vars ([Configuration](/configuration)), Admin → System Settings, and `createAuth()` overrides ([Authentication](/authentication#adding-another-provider)) all leave you on the update path.
- **Some code can't be changed locally.** The package's server modules bundle their own helpers: `lib/resend.ts`, `lib/auth-throttle*.ts`, `lib/request-info.ts`. Your project has copies of those files, but editing them doesn't change what the package's auth does. To change that behavior, replace `server/auth.ts` as described above. The auth route `app/api/auth/[...all]/route.ts` imports `@/server/auth`, so your version is the one that handles sign-in.

<Callout type="info">
Working on the template repo itself? There are no re-exports there: every file is the real source, and the package is built from it with `tsup`.
</Callout>

## Request flow

A request to a protected page passes three layers:

1. **`proxy.ts`** (Next 16's name for middleware) runs on every non-static route:
   - **Maintenance mode.** If it's on and the path isn't exempt, the proxy redirects to `/maintenance`, or returns `503` for `/api/*`. Admins bypass it. See [Admin & Maintenance](/admin#maintenance-mode).
   - **Dashboard gate.** `/dashboard/*` without a session cookie redirects to `/login?callbackUrl=…`. It only checks that the cookie exists, so it's cheap.
2. **`app/dashboard/layout.tsx`** calls `requireAuth()`. That validates the session against the database, signs out banned users and redirects them to `/login?error=account_banned`.
3. **`app/dashboard/admin/layout.tsx`** calls `requireRole('admin')`, which sends non-admins to `/dashboard`.

API routes don't go through the layouts. Each handler checks `auth.api.getSession()` and, for admin routes, `hasRole(role, 'admin')`, returning `401` or `403`. **Do the same in any route you add.**

## Adding a protected page

```tsx
// app/dashboard/reports/page.tsx — the dashboard layout already ran requireAuth()
import { requireAuth } from "@/lib/auth-helpers"

export default async function ReportsPage() {
  const session = await requireAuth() // cached per request, so this is free
  return <h1>Reports for {session.user.name}</h1>
}
```

For admin-only pages, put the page under `app/dashboard/admin/`, or call `requireRole('admin')`.

## Adding a protected API route

```ts
// app/api/reports/route.ts
import { NextResponse } from "next/server"
import { headers } from "next/headers"
import { auth } from "@/server/auth"
import { hasRole } from "@/lib/auth-helpers"

export async function GET() {
  const session = await auth.api.getSession({ headers: await headers() })
  if (!session) return NextResponse.json({ error: "Unauthorized" }, { status: 401 })
  if (!hasRole(session.user.role, "admin")) return NextResponse.json({ error: "Forbidden" }, { status: 403 })
  // ...
}
```

## Logging activity

Record anything an admin might later need to audit:

```ts
import { logActivity } from "@/lib/activity-logger"

await logActivity({
  userId: session.user.id,
  action: "profile_updated",           // an ActivityAction value
  description: "Changed display name",
  metadata: { from: "Ann", to: "Anne" } // optional, stored as JSON text
})
```

The action types are a fixed Postgres enum that ships in the package. For your own events, use the closest existing action and put the details in `metadata`. A genuinely new action type needs your own copies of `server/db/schema.ts` (add it to `ActivityActionEnum`, then `bun run generate` and migrate) and `lib/activity-logger.ts` (add it to the `ActivityAction` union). See [Customizing package code](#customizing-package-code).

## TypeScript

- Path alias `@/*` maps to the project root.
- Strict mode is on.
- In the template repo only: `tsup.config.ts` builds the npm package, and `tsconfig.build.json` limits `bun run typecheck` to the files that ship in it. Scaffolded projects don't have either.
